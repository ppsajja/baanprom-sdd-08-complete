# สิ่งที่ยังเป็นของจำลอง และข้อจำกัดที่รู้แล้วของ R1

ทุกข้อในไฟล์นี้ต้องเปลี่ยนเป็นของจริงหรือมีคำตัดสินก่อนเปิดให้ลูกค้าจริง (บทเสริม หัวข้อ 6.3 transition requirements) ข้อที่ต้องทำก่อนเปิดอยู่ในรายการตรวจของ docs/handover/hypercare-and-golive.md

## ของจำลองในโค้ด

| ของจำลอง | อยู่ที่ไหน | ทำอะไรแทนของจริง | ของจริงคืออะไร | เปลี่ยนเมื่อไร ใครรับผิดชอบ |
|---|---|---|---|---|
| Payment Gateway (IF-01) | backend/app/payments/gateway.py FakeGateway | ตอบ approved ทันทีทุกครั้ง ตั้งพฤติกรรมได้ผ่าน FAKE_GATEWAY_* บนเครื่องทดสอบ | class ที่เรียก API ของ gateway รายเดิมตามสัญญา (REQ-CON-003) ใช้ interface Gateway ตัวเดิม | ก่อนเปิดใช้จริง Dev lead และ Finance (ทดสอบ sandbox ของ gateway ทั้งตัดเงิน สอบถามสถานะ และคืนเงิน) |
| ระบบส่งข้อความ SMS หรือแอป (IF-02) | backend/app/notify/queue.py FakeNotifier | บันทึกว่าส่งแล้วโดยไม่ส่งจริง ข้อความดูได้จาก GET /notifications/queue | class ที่เรียกผู้ให้บริการ IF-02 (มีข้อตกลงประมวลผลข้อมูลแล้ว EV-048) | ก่อนเปิดใช้จริง Dev lead |
| LLM ของผู้ช่วย (IF-05) | backend/app/assistant/llm.py MockLLM | ตอบตามกติกาที่เขียนไว้ มีกรณีผิดให้ eval จับได้ ผล eval 20 จาก 20 จึงไม่ได้บอกว่า LLM จริงจะผ่าน | ผู้ให้บริการที่ผ่านเงื่อนไข Q-56 แล้วรัน eval ทั้งชุดใหม่ | งวด 3 ของ R2 ผู้ช่วยปิดอยู่จนกว่าจะรับ |
| บริการแผนที่ (IF-03) | backend/app/technicians/service.py distance_km | ระยะทางจากสูตร haversine ไม่ใช่ระยะตามถนน | เรียกบริการแผนที่ (timeout 5 วินาที MAP_TIMEOUT_SECONDS) | R2 หรือเมื่อ SH-06 ร้องเรียนว่าระยะไม่ตรง |
| ช่องทางถึงคนเวร | backend/app/ops/alerts.py Pager ส่ง webhook ไปที่ PAGER_WEBHOOK_URL | OAT-2 ทดสอบกับเครื่องรับ webhook ทดสอบ | บริการแจ้งเตือนเวรที่ Ops lead เลือก (EV-048) | วันติดตั้ง Ops lead (ทดสอบส่งจริง 1 ครั้ง) |

## สถานะที่อยู่ในหน่วยความจำ (หายเมื่อหลังบ้านเริ่มใหม่)

| สถานะ | ผล | ทางแก้ชั่วคราว |
|---|---|---|
| คิวข้อความ (notify/queue.py) | ข้อความที่ยังไม่ได้ส่งหายเมื่อเริ่มใหม่ (GAP-38) | หลังเริ่มใหม่ call center โทรหาลูกค้าที่มีนัดใน 2 ชั่วโมง ตามดุลยพินิจของ Ops lead |
| ตัวนับ /metrics และสถานะการเตือน | เริ่มนับใหม่ หลาย process นับแยกกัน | รันหลังบ้าน process เดียว (คู่มือติดตั้งขั้นที่ 5) |
คำถามที่ต้องตัดสิน: Q-67 (Ops lead งวด 1 ของ R2)

## ข้อจำกัดที่รู้แล้ว (ไม่ใช่ของจำลอง)

- ยังไม่มีการเข้าสู่ระบบ ผู้ขอบอกตัวเองด้วยรหัสที่ส่งมา (TH-01) GET /jobs/{id} ไม่ตรวจสิทธิ์ (GAP-24) จึงเปิดให้ลูกค้าจริงไม่ได้จนกว่า UC-02 มาใน R2
- AC-07-08 (ค้นหา 500 คนพร้อมกัน) ไม่ผ่านบนเครื่องทดสอบ CPU 2 ตัว ผ่านได้ถึงราว 200 คน (docs/acceptance/load-test-r1.md, Q-68)
- ตารางเวลาของช่างเติมได้ทางสคริปต์เท่านั้น ไม่มีหน้าจอ (operations.md เหตุการณ์ที่ 3)
- ช่างกดสถานะผิดย้อนกลับไม่ได้ (Q-30) call center เลื่อนนัดกลับแทนลูกค้าไม่ได้ (GAP-31)
- requirements.txt กำหนดแค่รุ่นต่ำสุดของ library (OAT-1 พบว่าติดตั้งใหม่ได้รุ่นใหม่กว่าเครื่องนักพัฒนา)
- ข้อมูลทั้งหมดในเคสนี้เป็นข้อมูลสมมติเพื่อการสอน


## สถานะหลัง R2 ส่วน A (Baseline B6)

- คิวข้อความไม่อยู่ในหน่วยความจำแล้ว (Q-67 ปิด CR-13) รันหลาย process ได้ ตัวนับของนาทีปัจจุบันยังหายได้ไม่เกิน 1 นาทีต่อ process
- มีการเข้าสู่ระบบแล้ว (UC-01 UC-02 CR-11) ระบบส่งข้อความยังเป็นของจำลอง (FakeNotifier) รหัส OTP จึงไม่ถึงโทรศัพท์จริง ในโหมด test และ development หน้าจอแสดงรหัสให้ (dev_code) โหมด production ไม่แสดง ต้องต่อ IF-02 จริงก่อนเปิดใช้
- บริการแผนที่ (IF-03) ยังเป็นสูตร haversine และหน้าลงทะเบียนส่งพิกัดกลางพื้นที่ทดสอบ (GAP-40) ระยะทาง BR-03 ของที่อยู่จริงยังผิดได้
- call center อ่านงานด้วยกุญแจของ Ops ตัวเดียว (GAP-32)
- AC-07-08 ผ่านบนเครื่องทดสอบตามความหมายของ Q-68 ยังต้องวัดบนเครื่องขนาดจริงก่อนเปิดใช้ (docs/acceptance/load-test-r2.md)
