# UC-02 ลูกค้าลงทะเบียนและเข้าสู่ระบบ (fully dressed)

ระบบ: บ้านพร้อม R2 | ผู้เขียน: กลุ่ม X | เวอร์ชัน: 1.0 (เข้า Baseline B6 ตาม CR-11) | ที่มา: TH-01, GAP-24, EV-051, หน้าบทเรียน Operational Security แถว A07:2025
เขียนขึ้นใน repo 08 เพื่อให้ชุด repo ต่อเนื่อง (B1 ถึง B5 มีเฉพาะชื่อใน use-cases.md)

| หัวข้อ | รายละเอียด |
|---|---|
| Primary actor | ลูกค้า |
| Secondary actors | ระบบส่งข้อความ (IF-02 ส่ง OTP) |
| Goal | ลูกค้ายืนยันว่าเป็นเจ้าของเบอร์โทร แล้วใช้ระบบในนามตัวเองได้ (precondition ของ UC-07 UC-08 UC-09 มุมมองลูกค้า และ UC-14) |
| Precondition | ลูกค้ามีโทรศัพท์ที่รับข้อความได้ |
| Postcondition (สำเร็จ) | ลูกค้ามีบัญชี 1 บัญชีต่อเบอร์ มีที่อยู่ให้บริการอย่างน้อย 1 แห่ง และมี session ที่ใช้ได้ 30 วัน |
| Postcondition (ล้มเหลว) | ไม่มี session ใหม่ ไม่มีลูกค้าซ้ำ |
| Trigger | ลูกค้าเปิดแอปโดยยังไม่เข้าสู่ระบบ |

## Main success scenario (ลูกค้าที่ลงทะเบียนแล้ว)

1. ลูกค้ากรอกเบอร์โทรและกดขอรหัส OTP
2. ระบบส่งรหัส 6 หลักไปที่เบอร์นั้นผ่าน IF-02 และบอกเวลาที่รหัสหมดอายุ (5 นาที BR-09 ข้อ 1)
3. ลูกค้ากรอกรหัส
4. ระบบตรวจรหัส ออก session 30 วัน และแสดงเมนูของลูกค้า

## Alternative flows

- A1 (ขั้น 4) ลูกค้าใหม่: ระบบขอชื่อและที่อยู่ให้บริการ ลูกค้ากรอกภายใน 10 นาที ระบบสร้างลูกค้า ที่อยู่ บัญชี และ session (REQ-FN-058)
- A2 (หลังเข้าสู่ระบบ) เพิ่มที่อยู่: ลูกค้าเพิ่มที่อยู่ได้หลายแห่ง และเลือกที่อยู่บนหน้าเลือกช่าง UI-07-01 (Q-29)
- A3 ออกจากระบบ: session ใช้ไม่ได้ทันที
- A4 ขอลบข้อมูล (ผ่าน call center REQ-PRV-010): บัญชีถูกลบ session ทุกตัวยกเลิก

## Exception flows

- E1 (ขั้น 3) รหัสผิด: ระบบบอกจำนวนครั้งที่เหลือ ผิดครบ 5 ครั้ง รหัสนั้นใช้ไม่ได้ กลับขั้น 1 (BR-09 ข้อ 2)
- E2 (ขั้น 3) รหัสหมดอายุ หรือมีรหัสใหม่กว่า: กลับขั้น 1
- E3 (ขั้น 1) ขอรหัสถี่เกิน 60 วินาที หรือเกิน 5 ครั้งในชั่วโมง: ระบบบอกให้รอ ไม่ส่งข้อความ (BR-09 ข้อ 3)
- E4 (ขั้น 2) IF-02 ไม่ตอบ: ระบบบอกว่าระบบส่งข้อความขัดข้อง ให้ลองใหม่ ไม่มีรหัสค้าง
