# UC-10 รับการแจ้งเตือนทาง SMS หรือ LINE (fully dressed แทนแบบ brief)

ระบบ: บ้านพร้อม R2 | ผู้เขียน: กลุ่ม X | เวอร์ชัน: 1.0 (เข้า Baseline B7 ตาม CR-17) | ที่มา: use-cases.md ส่วน 2 (brief), REQ-FN-012, EV-053 (SH-01 Ops lead SH-05)

| หัวข้อ | รายละเอียด |
|---|---|
| Primary actor | ลูกค้า และช่าง (ผู้รับ) |
| Secondary actors | ระบบส่งข้อความ (IF-02 SMS และ LINE) |
| Goal | ผู้รับได้ข้อความของงานภายใน 60 วินาทีทางช่องทางที่ตัวเองเลือก |
| Precondition | ผู้รับเข้าสู่ระบบแล้ว (UC-01 หรือ UC-02) |
| Postcondition (สำเร็จ) | ข้อความถูกส่งทางช่องทางที่เลือก มีบันทึกการส่งที่ไม่มีข้อความหรือเบอร์ |
| Postcondition (ล้มเหลว) | ข้อความอยู่ในคิว ส่งซ้ำตาม REQ-QA-010 |
| Trigger | งานเปลี่ยนสถานะ (UC-07 ขั้น 6, UC-08, UC-09, UC-05, UC-12, UC-13 A1) หรือผู้ใช้ตั้งค่าช่องทาง |

## Main success scenario (ตั้งค่า LINE)

1. ผู้ใช้เปิด "การแจ้งเตือน" เห็นช่องทางปัจจุบัน (ตั้งต้น SMS)
2. ผู้ใช้กด "เชื่อมบัญชี LINE" ระบบให้รหัส 6 หลักอายุ 10 นาที
3. ผู้ใช้พิมพ์รหัสในแชตของบัญชีทางการ LINE
4. LINE ส่ง webhook ระบบตรวจลายเซ็นและรหัส แล้วผูกบัญชี
5. ผู้ใช้เลือก LINE ข้อความถัดไปของงานไปทาง LINE

## Alternative flows

- A1 (ขั้น 5) ส่ง LINE ไม่สำเร็จ: ส่ง SMS แทนในรอบเดียวกัน บันทึกว่าเป็นการส่งแทน (BR-12 ข้อ 4)
- A2 ผู้ใช้ยกเลิกการเชื่อม LINE: ช่องทางกลับเป็น SMS
- A3 รหัส OTP ของการเข้าสู่ระบบ: ส่ง SMS เสมอไม่ว่าเลือกช่องทางไหน (BR-12 ข้อ 5)

## Exception flows

- E1 (ขั้น 4) ลายเซ็นผิด: 403 ไม่ผูก รหัสผิดหรือหมดอายุ: ไม่ผูก
- E2 (ขั้น 5) ยังไม่เชื่อม LINE แต่เลือก LINE: ระบบปฏิเสธ
- E3 ทั้งสองช่องทางไม่ตอบ: ข้อความอยู่ในคิว ส่งซ้ำทุก 5 นาที ไม่เกิน 6 ครั้ง (REQ-QA-010)
- E4 ผู้รับไม่มีเบอร์ (ลบข้อมูลแล้ว หรือช่างยังไม่มีบัญชี): บันทึก no_contact ไม่ส่งซ้ำ (BR-12 ข้อ 6)
