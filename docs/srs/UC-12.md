# UC-12 ช่างรับหรือปฏิเสธงาน (fully dressed)

ระบบ: บ้านพร้อม R2 | ผู้เขียน: กลุ่ม X | เวอร์ชัน: 1.0 (เข้า Baseline B6 ตาม CR-12) | ที่มา: MD-UCD-01, MD-STM-01, EV-051 (SH-06)

| หัวข้อ | รายละเอียด |
|---|---|
| Primary actor | ช่าง |
| Secondary actors | ระบบส่งข้อความ (IF-02) |
| Goal | ลูกค้ารู้เร็วว่าช่างรับงานหรือไม่ ไม่ต้องรอจนถึงวันนัด |
| Precondition | ช่างเข้าสู่ระบบแล้ว (UC-01) และมีงานที่มอบให้สถานะ "ยืนยันแล้ว" |
| Postcondition (รับ) | การตอบรับเป็น "รับงาน" สถานะงานไม่เปลี่ยน |
| Postcondition (ปฏิเสธ) | งานเป็น "กำลังหาช่างใหม่" ช่วงเวลาของช่างเป็น "ว่าง" ช่างไม่เห็นงานนี้อีก UC-05 เริ่ม |
| Trigger | งานเป็น "ยืนยันแล้ว" (UC-07 ขั้น 6 หรือ UC-05 ได้ช่างแทน) |

## Main success scenario

1. ระบบมอบงานให้ช่าง และแจ้งช่าง (UC-07 ขั้น 6)
2. ช่างเปิดรายการงาน เห็นปุ่ม "รับงาน" "ปฏิเสธงาน" และเวลาที่ต้องตอบ (30 นาที)
3. ช่างกด "รับงาน"
4. ระบบบันทึกการตอบรับ ปุ่มรับหายไป

## Alternative flows

- A1 (ขั้น 3) ช่างกด "ออกเดินทาง" (UC-09) โดยยังไม่กดรับ: ถือว่ารับงาน (BR-07 ข้อ 2)

## Exception flows

- E1 (ขั้น 3 หรือหลังขั้น 4 ก่อนออกเดินทาง) ช่างกด "ปฏิเสธงาน": ระบบบันทึก งานไป "กำลังหาช่างใหม่" แล้ว UC-05
- E2 (ขั้น 2) ไม่ตอบภายใน 30 นาที: ถือว่าปฏิเสธ (ไม่ตอบ) แล้ว UC-05
- E3 ช่างออกเดินทางแล้วกดปฏิเสธ: ระบบปฏิเสธคำขอ (ช่างทิ้งงานกลางทาง Q-51 ให้ call center)
- E4 ช่างคนอื่นส่งคำขอรับหรือปฏิเสธ: 403 และบันทึก (REQ-SEC-010)
