# UC-13 Finance กระทบยอดกับรายงานของ Payment Gateway (fully dressed)

ระบบ: บ้านพร้อม R2 | ผู้เขียน: กลุ่ม X | เวอร์ชัน: 1.0 (เข้า Baseline B7 ตาม CR-16) | ที่มา: MD-UCD-01 ("กระทบยอดปลายวัน"), Q-41, Q-72, สัญญา IF-01, EV-053 (Finance)
ชื่อเดิมใน MD-UCD-01 คือ "กระทบยอดปลายวัน" actor เดิมคือ "เจ้าของ หรือฝ่ายปฏิบัติการ" EV-053 ตัดสินให้ Finance เป็น actor หลัก

| หัวข้อ | รายละเอียด |
|---|---|
| Primary actor | Finance |
| Secondary actors | Payment Gateway (IF-01 รายงานประจำวัน) ระบบส่งข้อความ (IF-02) ผ่าน UC-10 |
| Goal | เงินในระบบตรงกับเงินที่ gateway รายงานทุกวัน และการคืนเงินที่ไม่รู้ผลถูกปิดโดยไม่ส่งคำขอซ้ำ |
| Precondition | Finance ใช้กุญแจของ Finance (REQ-SEC-015) และดาวน์โหลดรายงานของวันจาก gateway แล้ว (Q-72) |
| Postcondition (สำเร็จ) | มีผลกระทบยอดของวันนั้น 1 ชุด การคืนเงินที่ไม่รู้ผลซึ่งรายงานบอกผลถูกปิด ลูกค้าได้รับแจ้ง |
| Postcondition (ล้มเหลว) | ไม่มีอะไรถูกนำเข้า ระบบบอกเลขบรรทัดที่ผิด |
| Trigger | ทุกวันทำการ 10:00 น. Finance นำเข้ารายงานของวันก่อน |

## Main success scenario

1. Finance เปิดหน้า "กระทบยอด" เลือกวันที่และไฟล์รายงาน
2. ระบบตรวจทั้งไฟล์ตาม BR-13 ข้อ 1
3. ระบบรวบรวมการตัดเงินและการคืนเงินของวันนั้นฝั่งระบบ แล้วจับคู่กับรายงานด้วย (ชนิด, reference)
4. ระบบแสดงจำนวนที่ตรงกัน และรายการต่างแยกชนิด
5. Finance ตรวจรายการต่างทีละรายการตามคู่มือเหตุการณ์ที่ 8

## Alternative flows

- A1 (ขั้น 3) การคืนเงินที่ระบบ "ไม่ทราบผล" และรายงานบอกผล: ระบบเปลี่ยนผลตามรายงาน บันทึกที่มา แจ้งลูกค้า ไม่ส่งคำขอคืนเงินซ้ำ (BR-13 ข้อ 6 และ 8)
- A2 (ขั้น 1) รายงานเดิมของวันเดิมนำเข้าซ้ำ: ได้ผลชุดเดิม ไม่ทำซ้ำ (BR-13 ข้อ 9)
- A3 Finance เปิด "รายการติดตาม" ดูการคืนเงินที่ยังไม่ทราบผลทั้งหมด

## Exception flows

- E1 (ขั้น 2) ไฟล์ผิดแม้บรรทัดเดียว: ไม่นำเข้าอะไร ระบบบอกเลขบรรทัดและเหตุ
- E2 (ขั้น 3) รายงานไม่มีการคืนเงินที่ไม่รู้ผล: ยังเป็น "ไม่ทราบผล" อยู่ในรายการติดตาม
- E3 ผู้ใช้ที่ไม่ใช่ Finance (รวมกุญแจของ Ops และ call center): 403
