## 2. Use case แบบ brief

UC-08 ยกเลิกการจองและรับเงินคืน (brief)
ลูกค้ายกเลิกงานที่ยืนยันแล้วได้เองก่อนช่างออกเดินทาง ระบบแสดงยอดคืนตาม BR-01 ก่อนให้กดยืนยัน แล้วทำตามลำดับ BR-05 กรณีช่างกำลังเดินทาง (R3) ยังรอ Q-14 ระหว่างนี้ไม่อนุญาตให้ยกเลิก

UC-09 อัปเดตสถานะงานภาคสนาม (brief)
ช่างกดสถานะของงานตัวเองสามปุ่มตาม BR-04 ระบบบันทึกประวัติ (REQ-DAT-002) และแจ้งลูกค้า แอปช่างต้องทำงานได้แม้สัญญาณหลุด (REQ-OP-002)

UC-10 รับแจ้งเตือน (brief)
ทุกครั้งที่งานเปลี่ยนสถานะสำคัญ ระบบส่งข้อความถึงลูกค้าและช่างผ่านระบบส่งข้อความ (IF-02) ใน UC-07 ต้องส่งภายใน 60 วินาทีหลังสร้างงาน (REQ-FN-012)

ข้อความ brief สามข้อนี้เรียบเรียงจากภาพ Process Overview แบบ To-Be ในบทเรียน Modelling เพื่อให้ชุด repo ต่อเนื่อง

## 3. User story

### การ์ดตัวอย่าง

| ช่อง | ค่า |
|---|---|
| ในฐานะ | ลูกค้าที่แอร์เสีย |
| ฉันต้องการ | เห็นช่างที่ว่างจริงในสัปดาห์นี้ในเขตของฉัน |
| เพื่อ | ตัดสินใจจองได้ทันทีโดยไม่ต้องโทรสอบถามทีละร้าน |
| โยง REQ และที่มา | REQ-FN-008, EV-004 |
| เกาะ use case | เส้นทางหลักของ UC-07 |
| AC | AC-07-01 (booking.feature) |

ตัวอย่างที่ไม่ดี: "ในฐานะผู้ใช้ ฉันต้องการหน้าจอค้นหา เพื่อค้นหา" บทบาทกว้างเกิน ความสามารถเป็นชื่อหน้าจอ และคุณค่าวนกลับมาที่ตัวเอง

### แตก story การจองงานซ่อม

| รูปแบบ | ชิ้นที่ได้ |
|---|---|
| ตามขั้นตอนงาน | ค้นหาช่าง, เลือกช่วงเวลา, ยืนยันการจอง, ชำระมัดจำ |
| ตาม Business Rules | จองงานทั่วไป, จองงานด่วนภายใน 3 ชั่วโมง, จองล่วงหน้าเกิน 30 วัน |
| เส้นทางหลักกับข้อยกเว้น | จองสำเร็จ, ช่างปฏิเสธงาน, ลูกค้ายกเลิก, ชำระเงินไม่ผ่าน |
| ตามความหลากหลายของข้อมูล | งานซ่อมก่อน แล้วค่อยเพิ่มงานทำความสะอาดและจัดสวน |
| ตาม CRUD | สร้างการจอง, ดูการจอง, แก้ไขเวลา, ยกเลิก |
| ตามช่องทางหรือบทบาท | ลูกค้าจองเอง, call center จองแทนทางโทรศัพท์ |

กลุ่มเลือกแตกตามขั้นตอนงาน เพราะแต่ละชิ้นตรงกับขั้นของ UC-07 และมี AC ของตัวเองได้

### User Story Map (สองแถบ ลูกค้าและช่าง)

- แถว R1 คือ walking skeleton ลูกค้าจอง ติดตาม และยกเลิกได้ ช่างกดสถานะได้
- ทางชั่วคราว: การสมัครและเข้าสู่ระบบ (UC-01 และ UC-02) เลื่อนไป R2 ระหว่างนี้ R1 ใช้ลูกค้าคงที่หนึ่งคนและช่างคงที่ เส้นทางจึงเดินได้ครบ
- ใต้กิจกรรม "หาช่างและจอง" story ของ R1 คือขั้นของ UC-07 ที่รวม UC-03 และ UC-06 ส่วน A2 (call center จองแทน) และ UC-05 เลื่อนไป R2
- คิวรอ (waitlist) ยังไม่มีรหัส UC อยู่ในแถบยังไม่กำหนดรุ่น เช่นเดียวกับ UC-04 และ UC-12

## 4. Scenario ของ UC-07 (ผังเส้นทาง)

ใช้คำถามสี่ข้อขุดข้อยกเว้น: ข้อมูลขาดหรือช้า, ระบบภายนอกไม่ตอบ, ผู้ใช้ทำครึ่งทางหรือกดซ้ำ, สองคนทำพร้อมกัน
เส้นทางหลัก ทางเลือก A1 A2 และข้อยกเว้น E1 E2 E3 อยู่ใน UC-07.md
